设置

        

          

            
          

          

            
          

          

          

          

          

            
          

          

        

        
遇到 429 限流、402 积分耗尽、401/5xx 等可换号错误时，依次换下一个账号重试。「试完整个号池」会一直换到没有可用账号为止，此时最大重试次数不生效。

        
        

      


      

        
冷却与积分阈值

        

          

            
          

          

            
          

          

            
          

          

          

        

        
只有 429 限流 与 200108 账号异常 会冷却账号。
          429 默认只冷却出问题的那一个「账号 × 模型」：同一账号换别的模型仍然可用。
          冷却阶梯为 3 分钟 → 5 分钟 → 10 分钟，之后每次翻倍（封顶 24 小时）；冷却结束后该模型一旦调用成功即清零，
          下次再从 3 分钟算起。

          上游返回 200108「账号存在异常调用」时罚的是整个账号，换模型绕不过去：默认按账号级冷却，
          用的也是同一条阶梯（3 → 5 → 10… 分钟），到期自动恢复，调用成功即清零。

          403、5xx、网络错误视为上游波动：不冷却账号，直接换号重试。
          100041 / 100042（内容命中敏感词）是请求本身的问题，不换号、不冷却，直接返回 400。

          积分阈值独立于账号冷却：已知余额 ≤「暂停阈值」时该号暂停选号，等到 ≥「解除阈值」时自动恢复——
          通常配合签到使用，签到补上积分后立即解除，无需等冷却时间。解除阈值不能小于暂停阈值。

        
        

      


      

        
并发上限与排队

        

          

          

        

        
超过上限的请求不会直接返回 429，而是排队等待前面的请求结束；
          排队超过「最长排队时间」才返回 503。配置了 REDIS_URL 时计数跨实例共享，
          多副本合计也不超过这个上限；未配置 Redis 时只在单进程内计数。
          客户端在排队期间断开连接会立刻放弃，不会打到上游。保存后立即生效。

        
        

      


      

        
调度：单号串行、换号间隔与会话粘性

        

          

            
          

          

          

          

            
          

          

          

          

            
          

          

        

        
这三项都在回答同一个问题：「一次请求在外部看起来是什么形态」。
          上游风控看的不是单个请求，而是同一账号一段时间内接了多少互不相干的请求。

          单号串行：开启后同一账号同时只处理一个请求，其余请求自动换号；
          代价是单号并发能力下降，好处是不会出现「一台设备同时跑多段对话」。租约到期自动失效，
          进程崩溃留下的残租约也能回收；长回答会按租约时长的 1/3 滚动续期。

          换号间隔：失败后等一小会儿再换号，避免同一秒内横扫整个号池。

          失败后退避：403 / 5xx / 网络抖动这类上游波动会让该号在窗口内暂不被选中，
          时长从起点开始逐次翻倍、封顶上限。它不改变账号状态（面板上不会显示成停用），
          与「冷却」是两回事。调用成功即清空退避链。

          会话粘性：从 X-Session-Id / X-Conversation-Id /
          session_id / conversation_id 取会话标识，同一段对话优先复用上次成功的号；
          该号失败时立即解绑，避免一直撞同一个号。取不到标识时粘性自动不生效。保存后立即生效。

        
        

      


      

        
客户端指纹

        

          

          

          

          

          

          

        

        
这些值决定我们向小浣熊上游「以什么身份自称」，对话、签到、余额、续期全部共用一份。
          上游桌面客户端发版后，旧版本号会过期——「旧版本号 + 全新会话」是第三方客户端最典型的特征，
          所以版本变化时请在面板里直接改，不必重新发版。

          User-Agent 必须留成与版本号一致：留空会按版本号自动生成（如 raccoon-ai/1.0.35）。
          以前不发 UA，Go 会补 Go-http-client/1.1，与「自称桌面客户端」的其余头自相矛盾。

          「新号缺省系统版本 / 桌面平台」只影响之后新导入的账号；已有账号沿用入库时记录的值
          （在号池行里可单独改），不会因为这里改了就被批量改写——每号指纹必须保持稳定。保存后立即生效。

        
        

      


      

        
主动续期

        

          

          

          

        

        
小浣熊 token 有效期 30 天。转发路径只在有请求打到某个号时才刷新，冷门号可能长期不被选中，
          到期后会直接从号池消失。这里让后台定期把临期号统一续上；续期成功还会把「需重登」的号拉回在线。
          提前量或扫描间隔填 0 表示关闭。扫描间隔必须小于提前量，否则可能有号在两次扫描之间过期。
          保存后立即生效，无需重启。

单文件超过上限或跨天时自动轮转，旧归档按「保留天数」和「数量上限」中更严格的一条清理；调用流水与签到记录按「流水保留天数」从数据库删除。填 0 表示不按天数限制。
