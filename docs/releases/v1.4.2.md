## 更新日志

### 修复

**日日新账号导入报「未能从授权页取到登录 challenge」**

- 授权页的 `login_challenge` 只出现在 302 跳转的 `Location` 头里，而代码用的是
  会自动跟随跳转的 HTTP 客户端，等拿到响应时已经停在登录页，中间那一跳被吃掉了。
  现在改为手动逐跳跟随，每一步收 `Set-Cookie`、并把这些 Cookie 带到 IAM 登录接口。
- 授权页直接拒绝请求（例如 `error=invalid_state`）时，面板会显示上游给出的原因，
  不再笼统地报「取不到 challenge」。
- 登录前先调 `checkChallenge` 确认 challenge 仍有效，过期直接报错，
  不会白白消耗一次账号的失败次数。

**日日新导入后账号「能登录但发不出请求」（429/401）**

- 根因是建 API Key 打错了接口：旧接口 `/iam/idp/v1/apiKeys` 建出来的 Key
  没有 Token Plan 授权，调推理恒定 401 `Forbidden`。
  现在改为控制台「API-Key 管理」实际使用的
  `/lite/console/v1/metered/api-keys`，并带上 `key_type=API_KEY_TYPE_TOKEN_PLAN`。
- 实测链路：登录 → 建 Key → `/v1/models` 返回模型清单 → 读积分池额度，全部通过。
- 此前导入过的日日新账号，只要 Key 不可用，在面板点「查额度」或重新导入即可拿到新 Key。

**登录失败原因如实透出**

- 上游对账号锁定返回 `PermissionDenied`（`forbidLoginForMoment`），与「没有权限」
  共用同一个 reason，只能从文案里区分。此前一律落到兜底文案，
  很容易误以为账号密码填错了。现在会明确提示「账号被锁定，请 15 分钟后再试」。

### 升级说明

- 纯代码修复，无数据库改动，直接替换二进制或镜像即可。
- 之前导入失败、但账号密码正确的日日新账号，升级后重新导入即可。
- 若账号因连续失败已被上游锁定，需等待 15 分钟后重试。
