## 更新日志

### 新增功能

**调用日志页重做（服务端分页）**

- 以前打开「调用日志」会一次拉 200 条并整表渲染，流水一多页面就卡死。现在按页加载，
  默认每页 50 条，可选 20 / 50 / 100 / 200，支持跳页；历史流水再多页面也照样流畅。
- 筛选条：今天 / 昨天 / 近 7 天 / 近 30 天 / 全部，加状态下拉（成功 / 失败 / 4xx / 5xx）、
  账号、模型、接口、关键字搜索（模型 / 错误 / 接口 / 账号名或 uid）。
  所有筛选都在数据库里完成，不是把数据拉到浏览器再过滤。
- 表格按请求维度重排：时间、账号（名称 + uid）、状态、模型、接口、用时、用量
  （速度 + 输入输出明细）、错误摘要、详情。失败的请求整行标红，一眼能扫出来。
- 「详情」弹层显示单条请求的完整错误、token 明细和账号 uid。
- 「列设置」可以隐藏不常看的列，选择记在浏览器本地。
- 「自动刷新」可按 5 / 10 / 30 / 60 秒轮询，只在停留在本页且标签页可见时生效，
  切到别的页面或最小化浏览器即暂停，不会白白打后端。

**号池页表格**

- 号池改为密集表格：勾选、序号、账号、启用开关、状态、限流、有效期、余额、操作。
  可按「启用 / 停用」「正常 / 已限流」和关键字筛选，筛选结果可一键全选后批量操作。
- 「限流」列区分两级：账号级冷却显示原因和剩余时间；模型级罚单（429 只罚
  「账号 × 模型」）显示「N 个模型」，点开能看到每个模型的恢复倒计时，
  也支持单条「清除」或「全部解除」。
- 「查询余额」未勾选账号时查全部启用账号，勾选后只查选中的那批；逐个串行执行，
  避免同一出口 IP 并发查询触发风控。

### 修复

- **长回答被硬掐断**：以前上游请求用的是一个整体时限，边想边答的长回答到点就会被
  切断，报 `context deadline exceeded`。现在对话流改成「多久没收到上游数据算超时」，
  只要上游还在持续输出就不会被掐断；登录、查余额、拉目录这类非流式请求仍保留整体超时。
  新增环境变量 `UPSTREAM_TIMEOUT_SEC`（默认 120）控制后者。
- **模型冷却明细看不到**：账号整体显示「正常」时，某些模型其实还在 429 冷却，
  面板上没有任何提示。现在「限流」列会列出来。

### 升级说明

- 直接替换镜像或二进制即可，无需手工操作。
- 数据库新增一个索引（`usage_logs(account_id, id)`），启动时自动创建；旧库可直接打开，
  数据不受影响。
- 新增可选环境变量 `UPSTREAM_TIMEOUT_SEC`，不配置则沿用默认值 120 秒，已有部署无需改动。
- 调用日志页新增的筛选与分页需要新版面板与后端配套，请整体升级，不要只替换其中之一。
