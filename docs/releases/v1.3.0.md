## 更新日志

### 新增

**可选 Postgres 存储与 Redis 协调（默认行为不变）**

- **Postgres**：设置 `DATABASE_URL=postgres://...` 即改用 Postgres 存储，
  连接池默认 20/10。不设置时仍使用 `DATA_DIR/relay.db`（SQLite），
  现有单机部署无需任何改动。
- **旧库自动迁移**：首次切到 Postgres 且目标库为空时，启动会把
  `relay.db` 迁过去：
  - 先做 WAL checkpoint 再改名读取，不丢未合并的最新账号/Key；
  - 逐条用当前 `SECRET_KEY` 解密校验，不一致直接中止（不会导入一个打不开的库）；
  - 逐表比对行数，任一不等即回滚；
  - 成功后旧库改名为 `relay.db.migrated-<时间戳>`，失败则改回原名并中止启动。
  - `MIGRATE_SQLITE=off|auto|require` 控制该行为。
- **Redis**：设置 `REDIS_URL` 后，签到、冷却巡检、日志清理、主动续期在
  多个副本间只跑一份；API Key 校验结果可跨副本缓存。
  Redis 不可用时自动降级为进程内实现，不阻止启动；多副本建议设
  `REDIS_REQUIRED=1`。
- **全栈编排**：新增 `docker-compose.stack.yml`，一条命令拉起
  relay + Postgres + Redis（Redis 使用 `noeviction`，避免锁被驱逐）。
- **并发上限与排队**：`MAX_CONCURRENT` 限制同时转发到上游的请求数。
  超出的请求排队等待而不是返回 429，前面的请求结束后自动继续；
  排队超过 `QUEUE_WAIT_SEC`（默认 600 秒）才返回 503。
  配置 `REDIS_URL` 时计数跨实例共享，多副本合计仍受同一上限约束。
  默认 0（不限制），保持原有行为。并发上限与排队时长可在面板「设置」里修改。
- **单号并发上限**：可以给单个账号设同时承接的请求上限（0 = 不单独限制），
  支持单个设置、批量设置或一键应用到全部账号。达到上限的号会被选号器跳过，
  请求自动落到其它账号。`accounts` 表新增 `max_concurrent` 列，
  启动时自动为老库补列，无需手工迁移。

### 性能

- **API Key 校验**：3 条查询合并为 1 条并走新索引（此前 `hash` 无索引，
  每个请求都是全表扫描）；`last_used` 由每请求一写改为每 Key 60s 最多一写。
- **选号**：账号列表加 1 秒进程内快照（深拷贝），不再每次换号都全表读 + 逐行解密。
- **调用流水**：改为后台每 500ms / 每 100 条批量写入，请求路径不再等写锁；
  关闭时会把剩余记录刷完。
- **SQLite 写并发**：仍是单连接（现行为不变）；要真正并发请切 Postgres。

### 升级说明

- **SQLite 用户**：直接替换镜像或二进制，无需任何操作。
- **切换到 Postgres**：备份 `data/relay.db*` 后设置 `DATABASE_URL` 启动，
  看启动日志确认「已从 SQLite 迁移 N 个账号」。`SECRET_KEY` 必须与旧部署一致。
- **回滚到 SQLite**：清空 `DATABASE_URL`，把 `relay.db.migrated-*` 改回 `relay.db`。
- **多副本部署**：必须配置 `REDIS_URL`，否则每个副本都会跑一遍签到与清理。
  号池的在途计数与轮询序号仍是进程内状态，多副本下负载分布按实例计算。
- 多副本共享 `DATA_DIR` 时文件日志轮转不安全，建议设 `LOG_FILE_ENABLE=false`。
