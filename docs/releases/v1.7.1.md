# 小浣熊上游对齐 + 号池忙碌换号修复

本版主要把小浣熊（raccoon）这条链路按官方 1.1.5 的实测行为重新对齐，
并修掉一个「号池忙时直接放弃换号」的老问题。

## 修复

### 号池忙时不再放弃换号

积分不足（402 / 1000007）之后本该换号重试，但如果当时健康号都在处理别的请求，
旧实现只在第一次尝试时兜底探测，之后直接放弃，把上游的 402 原样丢给调用方。

- 换号时区分「号池空了」与「号都在忙」：后者短暂等待再选（上限 20 秒），
  等待不计入最大重试次数。
- 单号租约从「一个时刻」改为多槽位表，按主键 + 条件更新原子抢占，多副本不超发；
  启动时把仍在占用的槽位汇总回账号行。
- 新增「单号租约并发数」（默认 2）：
  - 环境变量 `LEASE_CONCURRENCY`；
  - 面板「设置 → 调度」可改，改完立即生效并持久化，重启后保持；
  - 1 = 整号串行；关闭租约仍是不限同号并发。

### 客户端取消不再记成上游故障

用户在客户端点停止、关页面时，旧实现会把这次失败记成 502 并给健康号记退避。
现在按「客户端断开」单独归类，流水记为 499，不参与失败率与耗时统计，
不冷却账号、不继续换号。

### 并发槽位满时误判池空

上一版把「号都在忙」当成「没有可用账号」，单号池在并发高于槽位数时会直接 502。
现在只有抢到槽位后才把号排除，抢不到时等待池内空出。

## 小浣熊上游对齐

对照官方客户端 1.1.5 的实测行为，补齐几处「号看着是好的、但实际不对」的地方。

### 错误识别

- 业务码同时认数字与字符串名字（`insufficient_points` / `rate_limit_exceeded` /
  `arrearage`）。字符串码以前会被当成「没有错误码」，于是积分耗尽被判成请求错误：
  既不换号也不冷却，那个没钱的号继续接单。
- 流里的错误帧不再被当成「坏帧」跳过。上游在流中途发字符串码时，旧实现会把它
  解析失败、跳过，最后表现为「上游返回空响应」。
- 429 按文案分流：明确指向余额的判积分耗尽（停到下次签到），其余仍是模型级限流。
- 内容策略拦截（`blocked by security policy` / `unapproved channel` /
  `illegal api invocation`）归为请求侧拒答：不冷却、不换号。
  这类拦截是上游对客户端模板句的逐字匹配，账号本身是健康的。
- 凭证失效补认 `200009` 与 `authorization_verify_error`；
  嵌套错误体（`{"error":{"message":…}}`）能直接取到可读文案，不再把整段 JSON 塞进面板。

### 会话标识

- 同一条对话现在跨轮共用同一个会话号。以前每轮都按整条消息重新派生，
  上游看到的是互不相干的请求。
- 工具调用后的续轮复用同一「轮次」标识；用户真的发了新消息才算新的一轮。

### 签到

- 改成以**账单**为准：先触发每日发放，再核对积分账单里今天实际入账多少。
  签到记录不再写死 0 积分，面板上能直接看到今天领到多少。
- 发放触发器在 v3 接口不可用时自动退到 v2，不再每天在第一步静默失败。
- 「今天」按北京时间算，不跟容器时区（海外/容器部署不会再错位一天）。

### 模型清单

- 上游标成不展示的内部模型保留在清单里（可以给它建别名映射），但不进 `/v1/models`。
- 补上目录里的计费倍率（按实付价展示，限免显示 0 倍）。
- 冷启动兜底不再编造上下文/输出上限，缺的值交给 models.dev 补齐。

## 升级说明

- 直接替换二进制或拉新镜像即可，没有需要手工执行的步骤。
- 数据库有新表（`account_lease_slots`）与若干列，启动时自动迁移，旧库可直接使用。
- 原有环境变量全部兼容。新增一个（只是首次启动的默认值，面板保存后以面板为准）：
  - `LEASE_CONCURRENCY`（默认 2，1 = 整号串行）
- 签到链路多了一次积分账单请求（约数秒）；自动签到按账号串行执行，
  整体耗时可能比之前略长。
