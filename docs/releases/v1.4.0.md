## 更新日志

### 新增功能

**接入商汤日日新（Token Plan）作为第二套上游**

- 号池按供应商分组展示：🦝 小浣熊 / 🌊 日日新，分组头可折叠，供应商筛选与状态、冷却筛选可叠加。
- 「添加账号」新增日日新页签：填控制台账号密码即可，
  自动完成 OAuth2 + PKCE 登录换登录票 → 创建推理 API Key → 读积分池额度，全程无需手工复制 Key。
- 日日新账号行直接显示「池 × 窗口」额度（5 小时池 / 7 日池 / 活动返赠），行菜单按钮变为「查额度」。
- 转发按账号供应商分流，按模型名自动路由到对应上游；`/v1/models` 合并两家模型清单。
- 日日新不参与签到与 refresh_token 续期，面板对这类账号显示「无签到」。
- 小浣熊账号行为完全不变；不添加日日新账号时，号池里只有一栏。

**用量报表页**

- 报表补齐为完整视图：
  - 统计概览：总 Token（输入/输出拆分）、成功请求数与成功率、Top 模型；
  - Top 账号 / Top 协议排行（进度条 + 占比）；
  - 模型 / 协议用量环形图，跨图统一配色；
  - 按天趋势：模型 / 协议 / 账号三个维度 × Token / 请求数两种指标，
    可下钻到单个实体；选「全部」时叠成堆叠柱并出图例；
  - 近一年活跃热力图，档位按当前窗口峰值自动计算，图例直接标出每档 Token 区间；
  - 耗时与吞吐：平均 / P50 / P95 / 峰值耗时、平均输出速度；
  - 账号统计、协议统计两张明细表（成功/失败、成功率、输入/输出，可按 Token 或请求数排序）。
- 区间支持今天 / 昨天 / 7 天 / 30 天 / 本月 / 全部，以及自定义起止日期。
- 报表读的是按天预聚合的小表，不扫流水大表；流水被清理后历史统计仍然保留。

**账号优先级**

- 账号新增「优先级」：数值大的先被选中，负载均衡与轮询两种策略都生效。
  想把主力号用光再切备用号，给主力号设更高的值即可；0 为默认，互不影响。

**上游错误分类与重试**

- 请求侧错误（上下文超长 11115、请求体过大 413、Schema 非法 4027）不再换号、不冷却账号，
  直接以 4xx 返回——换哪个号都是同一个请求体，重试只浪费时间。
- 这类错误即使在 200 流里以错误帧出现，也不会被当成上游波动去重试重放。
- 新增 `Retry-After` 解析：响应头的三种写法、响应体的九个字段名，毫秒 / 秒 / 时间戳四种量级都认。
- 429 冷却取「本地冷却阶梯」与「上游给出的重置时刻」中较晚的一个，并对外返回 `Retry-After` 头。
- 号池因冷却被抽干时，探测最早恢复的账号真打一次，把上游真实错误交给调用方，
  而不是一句笼统的「没有可用账号」。
- 业务码提取兼容 `error_code` / `data.code` / `ResponseMetadata` 等信封形态；
  流内的 Anthropic 形态错误帧不再被忽略。

**积分耗尽冷却到下次签到**

- 402 积分耗尽不再固定停到次日 04:00，而是停到该账号下一次签到补分的时刻；
  拿不到签到计划时才回退到次日 04:00。
- 上游以 HTTP 400 + 业务码 `1000007` 返回「积分余额不足」时，同样按积分耗尽处理：冷却并换号重试。

**客户端指纹补齐**

- 四套请求头（对话 / 管理 / 刷新 / 手机端 / 设备绑定）显式下发 `User-Agent`。
  此前漏发时 Go 会自动补 `Go-http-client/1.1`，与「自称桌面客户端」的其余头自相矛盾，
  是触发上游 200108「账号存在异常调用」的诱因之一。
- 版本号、系统版本、桌面平台、UA 改为可在面板「设置 → 客户端指纹」里修改，改完热生效；
  UA 留空时按版本号自动派生，改版本号不会残留旧 UA。
- 新导入账号的缺省平台 / 系统版本取当前指纹，不再写死常量。

**调度：单号串行、换号退避、会话粘性**

- **单号串行**：同一账号同时只接一个请求，其余排队落到别的号上。默认开启，
  在途租约写在数据库里（数据库 CAS），多副本下也不会互相抢号；
  进程崩溃留下的残租约到期自动失效，面板可手动解除。
- **换号退避**：403 / 5xx / 网络抖动这类临时失败后，该号在窗口内不被选中，
  2 秒起逐次翻倍封顶；成功即清零。这只影响调度，**不改账号状态**，面板上号仍是「在线」。
- **换号间隔**：两次尝试之间可配置等待，打断「同一秒横扫整个号池」的请求形态。
- **会话粘性**：同一段对话优先复用上次成功的账号，失败即解绑。
  上游风控看的是「同一账号在一段时间内接了多少互不相干的请求」，
  每轮重新选号会让对话在账号之间跳来跳去。
- 以上四项及冷却参数都可在面板修改并热生效；单号串行的 TTL、退避上限、粘性有效期均可调。

### 修复

- 报表趋势图图例与环形图配色不一致；下钻到单个实体后下拉只剩这一项、切不回「全部」；
  选定单一实体时柱高翻倍。
- 优先级字段此前虽然存在，但选号器并未使用——设置后不生效。
- 迁移工具读旧库时只判断部分新增列，旧库缺列会直接 SELECT 失败。

### 升级说明

- **SQLite 用户**：直接替换镜像或二进制启动即可。`accounts` 表会自动补上
  `lease_until` / `provider` / `sn_*` 列，报表聚合表会自动补列，并从现有流水补算一次历史日聚合，
  启动日志会打印「已从历史流水补算日聚合：N 条」。
- **Postgres 用户**：同样自动补列，无需手工迁移。
- **部署编排**：`docker-compose.stack.yml` 改为自包含单文件（补齐 image / ports / volumes / healthcheck），
  宝塔等只接受单个 compose 文件的场景可以直接用。原先的叠加用法仍可用，`docker-compose.yml` 未变。
- **行为变化**：
  - 单号串行默认开启。若某账号请求耗时很长，其他请求会落到别的号上；
    想恢复旧行为可在面板「设置」里关闭。
  - 403 / 5xx 不再把账号显示为「停用」，只做短时退避；如果一个号持续失败，
    面板上它仍显示在线，但短时间内不会被选中。
  - 日日新账号不参与签到与续期，这是预期行为。
- **环境变量**：新增项全部有默认值，老配置可直接启动；所有新增配置均可在面板修改并持久化。
