# 添加账号页按渠道重组，移除两个外部渠道

本版有两件事：面板的「添加账号」改成先选渠道再选方式，并补上一处会重复建号的
去重缺口；同时移除 AutoClaw 与码道 CodeArts 两个外部渠道。

## 新增功能

### 添加账号：先选渠道，再选添加方式

原来的标签把「粘贴授权码」「手填令牌」「日日新」「导入 JSON」平铺在一行，看不出
哪些属于同一家上游。现在：

- 一级标签按渠道分：**小浣熊 / 日日新**；「批量导入 JSON」用一道竖线隔开——
  它不绑渠道，一份文件里可以混装两家的账号。
- 「粘贴授权码」与「手填令牌」收进小浣熊栏，用二级分段切换。这是同一个渠道的
  两种取凭据方式，不该和「换个渠道」并列。
- 停在哪一栏、用哪种方式会被记住，刷新页面后回到原处。

### 导入结果按新增 / 更新 / 跳过分开报

此前导入完只显示「成功 N / 共 N 条」，重复导入时看不出到底新建了几个号。
现在分别统计三类，并逐条列出每个条目的 uid 与原因；原始 JSON 折进「原始返回」
里，默认收起，排障时再展开。

## 修复

### 日日新账号经导入包重复导入会多出一条

面板添加日日新账号时，账号标识记的是登录拿到的租户 ID；而凭据包里如果没有带
这个 ID，导入时退而用控制台账号（邮箱）当标识。两条路径进来的同一个号，标识
对不上，于是号池里出现两行。

现在导入与面板添加用同一套判定：先按控制台账号（不区分大小写）找，找不到再按
租户 ID 找。已存在就只更新凭据，不再新建。

## 移除外部渠道（行为变化）

AutoClaw 与码道 CodeArts 两条渠道整体下线。影响范围：

- 号池里不再有这两个供应商的分栏；「添加账号」页对应标签移除。
- 设置页的「外部渠道上游地址」卡片移除，`AUTOCLAW_*_BASE` / `CODEARTS_*_BASE`
  环境变量不再读取（留着不会有副作用，也不会生效）。
- 导出包不再包含这两家的账号；导入包里这两家的条目会被跳过并计入「已过滤」。

**号池里遗留的这两家账号会被标成「渠道已下线」**，单独成组，不会参与选号，
可以用号池页的「清理失效」一键移除。它们不会被自动删除——升级本身不动这些行，
想保留记录的话升级前先用旧版导出一份备份。

## 升级说明

- 直接替换二进制或拉新镜像，无需手工操作。
- 数据库方面：`accounts` 表的 `ext_*` 列不再由程序创建。**旧库中已有的这些列
  不会被删除**，新版在读写时忽略它们，升级与回滚都不会损坏数据——已验证
  v1.7.2 建的库可被本版直接打开，账号数据完整。
- 其它环境变量与设置项全部兼容。
