# 小浣熊反代 · Raccoon Relay

把商汤小浣熊（xiaohuanxiong.com）的对话能力包成一个自托管的 OpenAI / Anthropic 兼容网关。
单二进制、单端口、纯 Go、无 cgo，只做三件事：**反代对话、号池轮换、自动签到**。

> 友链：[LINUX DO](https://linux.do/) —— 本项目在 LINUX DO 社区推广

> 致谢：错误分类、`Retry-After` 对齐、请求侧错误隔离与报表页的设计，
> 参考了开源项目 [aigw-backend](https://github.com/)、[Agent2API](https://github.com/)、
> [AgentHub](https://github.com/) 的思路，在此致谢。

## 快速开始

### 直接拉镜像部署（推荐）

```bash
cp .env.example .env
# 至少填这两项（都是随机串即可）：
#   ADMIN_TOKEN=<自己定一个>
#   SECRET_KEY=<自己定一个，别改>
docker compose up -d
docker compose logs relay
```

默认从 Docker Hub 拉 `bxacc123/raccoon-relay:latest`。指定版本用 `IMAGE_TAG`：

```bash
IMAGE_TAG=2026.11.13 docker compose up -d
```

### 换成 Postgres + Redis（多实例 / 更高并发）

默认单容器用 SQLite，读多写少够用；但 SQLite 只有一个写连接，
高并发时所有请求会排队等写锁。需要更高并发或多副本时用全栈编排：

```bash
# .env 里额外填 POSTGRES_PASSWORD、REDIS_PASSWORD
docker compose -f docker-compose.yml -f docker-compose.stack.yml up -d
```

这一套会一起拉起：

| 服务 | 作用 |
|---|---|
| `relay` | 应用本身 |
| `postgres` | 业务数据（账号、Key、流水、冷却、事件） |
| `redis` | 后台任务分布式锁（签到/巡检/清理/续期只跑一份）+ Key 校验缓存 |

已有 SQLite 数据时按原样把 `./data/relay.db*` 放好再启动：relay 会自动
checkpoint WAL、把数据导入 Postgres，并把旧库改名为
`relay.db.migrated-<时间戳>`。迁移会逐条校验 `SECRET_KEY` 与行数，
任何不一致都会中止启动并回滚，不会静默起一个空库。

也可以只连外部 Postgres / Redis，不启用这个文件，在 `.env` 里设置：

```bash
DATABASE_URL=postgres://user:pass@host:5432/relay?sslmode=disable
REDIS_URL=redis://:pass@host:6379/0
```

`DATABASE_URL` 留空仍是 SQLite。想回滚到 SQLite：清空 `DATABASE_URL`
并把 `relay.db.migrated-*` 改回 `relay.db` 即可。

### 并发上限与排队

号池能同时承载的请求有限。设置并发上限后，超出的请求**不会直接返回 429**，
而是排队等待前面的请求结束：

```bash
MAX_CONCURRENT=8      # 0 = 不限制（默认）
QUEUE_WAIT_SEC=600    # 最长排队时间，超时返回 503
```

- 队列不靠内存堆积请求对象，而是 Redis 里的计数槽位（`ZSET`），
  进程崩溃留下的槽位按 30 分钟 TTL 自动回收。
- 配置了 `REDIS_URL` 时计数**跨实例共享**：两个副本各跑 4 个、
  上限 8，合计仍是 8。
- 未配置 Redis 时退化为进程内计数，单实例行为一致。
- 客户端在排队期间断开，会立刻放弃，不会再打上游。

### 单号并发上限

除了全局上限，还可以给单个账号设并发上限，防止某几个号被压得太狠：

| 设置方式 | 位置 |
|---|---|
| 单个账号 | 号池页 → 该行「设置」→ 并发上限 |
| 批量设置 | 勾选若干账号 → 「批量操作」→ 设置并发上限（选中） |
| 全部账号 | 「批量操作」→ 设置并发上限（全部） |

填 `0` 表示不单独限制。达到上限的号会被选号器跳过，新请求自然落到别的号上；
所有号都满载时才会回到全局排队。账号列表里会在账号名下方标出「并发≤N」。

## 加账号

### 方式一：粘贴授权码（推荐）

1. 面板「添加账号 → 粘贴授权码」点「打开小浣熊登录页」。
2. 浏览器里完成登录，收尾会跳到 `office-raccoon://auth/callback?code=…`：
   - **没装桌面客户端**：浏览器提示"没有可用应用"，地址栏里就是完整链接，整段复制。
   - **装了桌面客户端**：深链会被客户端吃掉，授权码会被它消费掉（再兑换会报 `200035`）。
     此时用无痕窗口重新走一遍，或者直接用手填令牌。
3. 把整段链接粘进面板，点「兑换并添加」。

后端做的是纯 HTTP：`POST /api/web/auth/v1/login_with_authorization_code` 换 token →
解 JWT `sub` 取 uid → 派生并绑定设备指纹 → 入池。容器只负责兑换，不参与回调。

### 方式二：手填令牌

从桌面客户端的 `~/.box-agent/config/auth.json` 里拷三个键：

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "office_identity": ""
}
```

填进面板「手填令牌」。`access_token` 必须是合法 JWT 且带 `sub` 声明，否则会被拒绝——
`iss` 是所有账号共用的签发方常量，拿它当 uid 会让整池塌成一个号。

### 方式三：导入 JSON

直接导入桌面版导出的凭据包：

```json
{
  "format": "agenthub-credentials",
  "channel": "raccoon",
  "accounts": [
    { "channel": "raccoon", "uid": "pu-...", "token": "...", "refreshToken": "...", "meta": {...} }
  ]
}
```

按 `uid` 去重：已存在的账号合并凭据与 `meta`（保留 `onboardingGrants` / `checkin` / `deviceId`），不会重复建号。
导出走同一格式，可以直接回灌桌面版。

号池「导出 JSON」默认导出全池；勾选账号后再点，则只导出选中的号（文件名带 `selected-<条数>`）。
包里同时包含两种供应商：小浣熊账号与桌面版格式完全一致；日日新账号 `channel` 为 `sensenova`，
除 API Key（`token`）外还带 `username` / `password` / `consoleToken` / `consoleRefreshToken`，
导出结果可以直接导入回来继续自动续期与重登。

也兼容 agent2api 的桌面导出（`{"version":2,"exportedAt":...,"accounts":[{"provider":...}]}`）。
这种包是多供应商混装，导入时只保留小浣熊账号（`provider` 为 `raccoon`；缺失时按 token 的
`iss = xiaohuanxiong.com/iam` 判别），其余 qoder / trae / codearts 等会被自动过滤，
面板会提示过滤掉多少条。agent2api 的 token 放在 `pluginSecret.accessToken`，里面没有
独立的 `refresh_token` 字段；小浣熊这两个本来就是同一枚凭据，导入时直接用 `accessToken`
回填 `refreshToken`，所以导入的号一样能自动续期。

### 添加商汤日日新（Token Plan）账号

除小浣熊外，本项目也支持**商汤日日新 Token Plan**（`platform.sensenova.cn`）。
它是另一套上游：推理走 `https://token.sensenova.cn/v1`（OpenAI 兼容、API Key 鉴权），
额度则挂在控制台的 OAuth 登录票后面。所以导入方式是**控制台账号密码**：

- 面板「添加账号 → 日日新账号」填控制台账号（手机号/邮箱）与密码；
- 服务端用账号密码走 OAuth2 授权码 + PKCE 登录，换到控制台登录票，再在控制台
  「API-Key 管理」同一接口下自动创建一枚推理 API Key，和账号一起入库；
- 已经有 Key 的话也可以在「API Key（可选）」里直接填，跳过创建。

账号密码用于换登录票、读积分池与补建 Key，日常转发只用 API Key。号池页把两种账号
**分开成两个分组**（🦝 小浣熊 / 🌊 日日新），日日新行展示的是「池 × 窗口」的额度条，
而不是单一积分。日日新没有每日签到，所以不进签到中心、也不参与自动签到。

## 号池

每个请求按策略选号，失败自动换号重试（默认 3 次）。面板「设置」页可切换，改完立即生效。

| 策略 | 排序 |
|---|---|
| `load_balance`（默认，负载均衡） | 在途请求最少 → 最久未用 → 积分多者 → 先到期者 |
| `round_robin`（轮询） | 最久未被选中的优先，请求均匀摊到每个号上 |

> 旧版本里的 `optimal` / `credit_first` / `manual` / `expire_first` 升级后自动按「负载均衡」处理，
> 无需改环境变量。面板里改的选号策略、重试、签到时间、冷却阈值、续期与日志设置都会落库，
> 重启后仍然生效；环境变量只提供首次启动的默认值。

失败分级：

| 上游返回 | 处理 |
|---|---|
| 402 积分不足 / 1000007 积分余额不足 | `exhausted`，冷却到额度真正恢复：小浣熊停到该账号**下一次签到补分**（自动签到关闭时回退次日 04:00）；日日新停到**额度窗口的 `reset_at`**（5 小时/本周取较晚者）。立即换号重试 |
| 429 限流 | **只冷却「这个号 × 这个模型」**，账号保持在线；冷却阶梯 3 → 5 → 10 分钟，之后逐次翻倍（封顶 24 小时），该模型再次调用成功即清零。上游给了 `Retry-After` / `reset_time` 时按**较长的那个**冷却，并把剩余秒数回传给调用方 |
| 5xx / 网络错误 | 视为上游波动：**不冷却账号**，直接换号重试 |
| 上下文超长（11115 等） | 请求内容超模型上限：**不换号、不冷却**，直接回 400，提示精简上下文 |
| 请求体过大（413） | 请求侧体积问题：**不换号、不冷却**，直接回 413 |
| 参数 / Schema 非法（4027） | 请求格式问题：**不换号、不冷却**，直接回 400 |
| 号池暂时抽干 | 不直接回「没有可用账号」：挑一个最早恢复的号**实打一次**，把上游真实错误（含 `Retry-After`）交给调用方 |

完整分类顺序与处置见 [`docs/UPSTREAM-BEHAVIOR.md`](docs/UPSTREAM-BEHAVIOR.md)。
| 401 / 令牌过期 | 先用 `refresh_token` 强刷一次并重放；刷得动就继续用，刷不动才判 `relogin` |
| 403 风控/权限 | 视为上游波动：**不冷却账号**，直接换号重试。403 **不等于**凭证过期，不会把号打成 `relogin` |
| 凭证失效（refresh 也失败） | `relogin`，等重新导入凭据 |
| 模型级错误（6004 / 11102） | 只冷却「这个号 × 这个模型」，换模型仍可用 |
| 200108 账号异常 | 上游判定整个账号存在异常调用：**账号级阶梯冷却**（3 → 5 → 10… 分钟，封顶 24 小时），到期自动恢复、调用成功即清零。换模型绕不过去，所以整号跳过；面板可关闭该行为 |
| 100041 / 100042 敏感词拒答 | 上游对**请求内容**拒答，与账号无关：**不冷却、不换号**，直接回 400 给调用方 |
| 客户端断开 / 写回失败 | 不冷却账号、不再换号重试：请求方已经不在了，失败与上游无关。流水记 **499**，面板单列「客户端取消」，不计入失败数与成功率 |

### 积分阈值冷却

面板「设置 → 冷却与积分阈值」可开启：

| 项 | 说明 |
|---|---|
| 低于该积分暂停 | 已知余额 ≤ 该值的账号暂停选号（`exhausted`，无固定到期时间） |
| 达到该积分解除 | 余额 ≥ 该值时自动恢复在线 |

余额由签到、新号导入与手动「查余额」异步更新，写入成功后立即按阈值重算。
此外还有一条可配置的**余额巡检**（面板「设置 → 余额巡检」，环境变量
`BALANCE_SYNC_INTERVAL_MIN` / `BALANCE_SYNC_STALE_MIN`）：默认每 10 分钟巡一轮，
只查超过 30 分钟没更新读数的启用账号。它补的正是「签到失败没刷到」和
「日日新根本没有签到」这两类号——否则面板上的余额会长期停在旧值。
规则开启时「解除阈值」必须**大于**「暂停阈值」（相等会让状态在阈值上反复翻转）。
402 / 1000007 造成的硬耗尽（带恢复时刻的到期时间）不受此规则影响，到点由冷却巡检自动放回在线。
日日新的冷却到期会先核对一次余额：窗口过去了但读数仍是 0 时保持冷却，等额度真正回来再放；
查询失败时按到期时间放行，不会因为一次读失败把号永久关着。
该核对依赖余额巡检的新鲜读数，所以关闭巡检后日日新的到点复活也会变得保守（读数停在旧值）。
「429 按账号 × 模型冷却」开关关闭后，429 退化为整号冷却 60 秒。
「200108 账号异常按账号冷却」默认开启；关闭后这类响应不冷却账号，只换号重试。

### 账号优先级

每个账号可以设一个「优先级」（面板「号池 → 编辑账号」）。数值大的先被选中，两种选号策略都遵循它：

- 想让某个号先用光、再切备用号：把主力号优先级设高（例如 10），备用号保持 0；
- 优先级相同的号之间仍按所选策略（负载均衡 / 轮询）排序，不影响原有公平性。

### 用量报表

面板「报表」页按天聚合展示用量，不随调用流水清理而丢失历史：

- **统计概览**：总 Token（含输入/输出拆分）、成功请求数（含成功率）、总请求数、
  活跃天数、当前连续天数、Top 模型；
- **Top 账号 / Top 协议**：带进度条与占比的排行；
- **模型用量 / 协议用量环形图**：中心显示区间总量，右侧图例逐项列出 Token 与占比，
  同一模型在环形图、排行、趋势图里颜色一致；
- **按天趋势**：可切「模型 / 协议 / 账号」维度与「Token / 请求数」指标，
  并可在下拉里下钻到单个实体；维度为「全部」时叠成堆叠柱并显示图例；
- **活跃热力图**：固定近 365 天，按当天 Token 用量着色；档位按本窗口峰值自动定，
  图例里直接标出每档对应的 Token 区间；
- **耗时与吞吐**：平均 / P50 / P95 / 峰值耗时与平均输出速度；
- **账号统计 / 协议统计明细表**：请求数、成功 / 失败、成功率、总 Token、占比、输入 / 输出，
  账号表可按 Token 或请求数排序。

区间可选今天 / 昨天 / 7 天 / 30 天 / 本月 / 全部 / 自定义（起止日期）。日聚合在写流水时
同步累加，老版本升级上来时会自动从历史流水补算一次（启动日志会打印补算条数）。
对应接口：`GET /api/report?range=7|30|today|yesterday|month|all|custom&start=YYYY-MM-DD&end=YYYY-MM-DD`。

> 协议统计按出站协议（openai / anthropic / responses）汇总，数值全部来自真实流水。
>
> **缓存命中率**：上游回传缓存字段时会展示（OpenAI 的 `prompt_tokens_details.cached_tokens`、
> Anthropic 的 `cache_read_input_tokens`）。上游不传时不输出该字段、面板显示「—」，
> 而不是伪造一个 0% ——「不知道」和「没命中」是两件事。
>
> 上游的前缀缓存**按账号隔离**，所以会话粘性直接决定命中率：同一段对话每轮换号，
> 缓存必然全部未命中。粘性取 `X-Session-Id` / `X-Conversation-Id` / `session_id` /
> `conversation_id` / `prompt_cache_key`；客户端一个都不发时，可开启「按首条消息兜底」
> 用首条 user 消息派生绑定键（见设置页「调度」卡片）。

### 号池表格

面板「号池」页是一张密集的账号表，每行依次是：勾选、序号、账号（名称 + uid）、启用开关、
状态、限流、有效期、余额、操作。顶部可以按「启用/停用」「正常/已限流」和关键字（账号名 /
uid / 备注）筛选，筛选结果可一键全选后批量启用、停用、签到、解除冷却或删除。

**限流**列要分开看两级：

- 账号级冷却（`cooling` / `exhausted` / `relogin`）：显示原因和剩余时间。冷却中与
  「需重登」的格子带「· 详情」，点开是这个号最近的失败现场（见下）；
  账号级阶梯冷却（200108 账号异常）会额外显示「第 N 次」，说明这条失败链已经累积了几档；
- 模型级罚单（429 只罚「账号 × 模型」）：显示「N 个模型」，点开可看到每个模型的原因、
  恢复倒计时，也可以单条「清除」或「全部解除」。手动解除会同时清空该组合的失败链，
  下次再 429 从 3 分钟重新算。

**错误详情**

面板上只写「HTTP 403」是不够的——403 的真实原因（网关拦截码、风控文案、权限提示）
几乎都在上游的响应头和响应体里。点「限流」列里的「详情」，或行末 `…` 菜单的「错误详情」，
可以看到：

- 账号当前状态、冷却原因与恢复时间、模型级限流明细；
- 最近 5 次转发失败的完整现场：上游返回码、接口路径、turn ID、上游请求 ID、
  请求摘要（模型 / 客户端 / 平台 / 设备指纹 / 会话）、脱敏后的响应头、原始响应体、处置动作；
- 「复制全部」和「在运行日志中查看」（自动按「这个号 + 转发请求 / 号池冷却」筛好）。

`Set-Cookie`、`Authorization` 这类可能带凭据的响应头会被过滤，不会出现在面板上；
响应体超过 3000 字符按字符截断（不会切坏汉字）。

对应接口：`GET /api/accounts/{id}/errors`，返回最近 5 条 `relay` 事件与账号冷却状态。

> 这次改动之前产生的冷却号，事件表里没有它们的现场，点开只会提示「等下一次失败后再看」。
> 号池跑起来后新出现的失败就都有完整详情了。

账号整号状态显示「正常」时，模型级罚单仍然可能拦着某个模型——这正是这一列存在的意义。

「查询余额」未勾选账号时查全部启用账号，勾选后只查选中的那批；查询逐个串行执行，
避免同一出口 IP 并发查余额触发风控，单个号失败只标注该行，不影响其它号。

对应接口：`POST /api/accounts/balances`（`{"ids":[...]}` 可省略表示全部启用账号）、
`POST /api/accounts/batch`（`{"action":"enable|disable|delete|checkin|uncool","ids":[...]}`）、
`POST /api/accounts/{id}/uncool`（带 `{"model":"..."}` 只解该模型，否则解账号级冷却）。

### 清理失效账号

面板「号池」页的「清理失效账号」按钮会删掉所有**救不回来**的号：

| 口径 | 说明 |
|---|---|
| `relogin` | refresh_token 也刷不动，只能重新登录拿新凭据 |
| `expires_at` 已过 | 订阅到期，凭据能用也不会再产出额度 |

`exhausted`（积分耗尽）和 `cooling`（临时冷却）**不算**：它们会自己恢复，删了就回不来。

点按钮会先拉一份预览清单列给你确认；确认后只提交这份 id，后端删除前会再按最新状态复核，
预览之后被「刷新」救回来的号不会被误删。删除在单个事务里完成，连带清掉该号的
`model_cooldowns` 与 `checkin_history`，不会留下孤儿行。

对应接口：`GET /api/accounts/dead`（预览）、`POST /api/accounts/dead/purge`
（必须带 `{"ids":[...]}`；空请求体会被拒绝，避免误删）。

已经向客户端写出内容之后不再换号重试，避免拼出半截回复。

## 自动签到

小浣熊的每日积分是**两步懒结算**：先 `GET setting_info` 激活当日 Web 会话，再
`POST desktop/v1/login/points/grant` 领取。少第一步会一直拿到 `granted:false` 且积分不落账。

- 计划时刻 = `CHECKIN_HOUR:CHECKIN_MINUTE` + 按 uid 派生的 `0~CHECKIN_JITTER_MINUTES` 分钟抖动。
  同一账号每天固定、重启不变，不同账号自然错开。
- `granted:true`（本次领到）和 `granted:false`（今日已领过）**都算当日完成**，都写 `last_checkin_day`。
- 401 → 标记 `relogin`，当日不再重试；5xx → 不标记，下一轮自然重试；同号当日连续失败 3 次 → 熔断。
- 账号之间串行，间隔 800~2000ms 随机，防风控。
- 顺带领一次性首登奖（桌面端 + 手机端两条互不相通的端点各领一次），台账存账号 `meta.onboardingGrants`；
  端点返回 404/410 就记 `-1` 永久停试。
- 每轮顺带刷一次余额。余额走 `GET office/v2/setting_info` 的 `available_points`
  （网页版头部同源）；`office/v3/setting_info` 自 2026-11 起被网关整体拦截（403，
  响应头 `X-TT-System-Error: 3`），留作第一回退；旧 `points/v1/balance` 已下线，只作最后兜底。
- 启动时会补跑：错过窗口不会漏签。

面板「号池」页全选后「批量操作 → 批量签到」可以手动触发一轮，也可以在账号行菜单里单独签到。

### 签到中心

面板顶部的「签到中心」页把签到相关的视图集中到一处：

- **顶部概况**：今日已签 / 待签 / 失败 / 累计记录（附累计领取积分），一键「立即签到」跑完整号池。
- **定时签到**：显示开关、执行时刻、抖动范围与下次执行时间，可直接跳到设置页。
- **账号签到**：每个号今天最后一次的结果与来源，可按全部 / 已签 / 待签 / 失败筛选，行内「补签」按钮单独重试。
- **签到记录**：每次签到一行，支持时间窗、结果（领取成功 / 今日已领 / 失败）、来源
  （定时任务 / 手动签到 / 新号落地）、账号与关键字筛选，服务端分页。

手动签到无论成败都会落记录——失败不写的话，签到中心会一直显示「今日未执行」，
重复点击也看不出变化。停用的账号不参与「今日已签 / 待签」统计。

## 配置

全部走环境变量，见 `.env.example`。几个值得注意的：

- `SECRET_KEY`：换了这个值，库里已加密的 token 就解不开，需要重新导入。
- `REFRESH_WINDOW_SEC`（默认 300）：转发路径上，access 只在临期 5 分钟内才刷。**不要调大**——
  抢在官方客户端前面刷新会把 `refresh_token` 轮换掉，两边同时掉登录。
- `RENEW_WINDOW_SEC`（默认 259200 = 3 天）/ `RENEW_INTERVAL_MIN`（默认 360）/
  `RENEW_GAP_MS`（默认 1000）：后台主动续期。小浣熊的 token 是 30 天有效期的 JWT；
  转发路径只在有请求打到某个号时才刷新，冷门号可能几周不被选中，到期后直接从号池消失。
  主动续期每 6 小时扫一遍，把 3 天内到期的号统一刷新，续期成功还会把被误判成
  `relogin` 的号拉回在线。设 `RENEW_WINDOW_SEC=0` 可关闭。
  这三项也可以在面板「设置 → 主动续期」里改，**保存后立即热生效**（循环按新参数重排，
  不需要重启），并持久化到数据库；环境变量只提供首次启动的默认值。同一张卡片上还有
  「立即续期一次」按钮，手动触发一轮并返回检查/续期/失败/恢复的条数。
- `OAUTH_REDIRECT_BASE`：配了才会启用 `/oauth/callback` 回环回调路径。
  取决于上游是否接受自定义 `redirect_uri`，实测能用再开；不能用并不影响粘贴授权码那条路。
- `CLIENT_VERSION` / `WEB_CLIENT_VERSION` / `CLIENT_OS_VERSION` / `CLIENT_PLATFORM` /
  `CLIENT_USER_AGENT` / `WEB_USER_AGENT`：发往上游的客户端指纹（详见下节）。
  面板「设置 → 客户端指纹」里改，保存后立即生效并持久化；环境变量只提供首次启动的默认值。

## 网关出站改写：指纹脱敏与开发者角色兼容

面板「设置 → 网关 · 出站改写」。两者都**只改发给上游的那份副本**：客户端发来的原文
与上游返回的响应都不变。

| 项 | 作用 | 默认 |
|---|---|---|
| 出站请求指纹脱敏 | 按词表改写发给上游的文本（system / user / assistant 等消息正文、推理内容与工具参数） | 开启 |
| 应用提供商 | 留空 = 全部提供商；勾选后只对勾选的生效 | 全部 |
| 开发者角色兼容 | 转发前把 `role:"developer"` 的消息改写为 `"system"` | 开启 |

**为什么脱敏**：上游按「连续文本」逐字匹配客户端指纹（Claude Code / Codex CLI 的身份句、
`x-anthropic-billing-header`、`cc_*=` 参数等）。内置词表对每一条都只做**最小改写**，
让指纹失配即可，不改动你的项目规范与工具说明。词表可以在面板里增删改、导入导出；
「恢复内置词表」把编辑结果清空并回到出厂那一份。规则可选「字面 / 正则」两种匹配方式，
正则删除规则可以勾「重复清理」直到文本不再变化；其余规则只执行一轮，避免文本被反复扩张。

**为什么角色归一**：OpenAI 新版 API 用 `developer` 取代 `system` 承载指令，但部分
OpenAI 兼容上游不认识这个角色，会直接 400。归一只改 role 字段本身，消息内容与顺序都不动；
在脱敏之前执行，后面各层看到的都是统一形态。

三项都在面板里改，保存后**下一个请求立即生效**并持久化到数据库；环境变量
（`SANITIZE_ENABLE` / `SANITIZE_PROVIDERS` / `DEVELOPER_ROLE_COMPAT`）只提供首次启动的默认值。

## models.dev 模型元数据

面板「设置 → models.dev 模型元数据」。用 [models.dev](https://models.dev)（社区维护的模型资料库）
补齐「上游没告诉我们」的模型能力：上下文窗口、最大输出、工具调用、图片、视频、是否支持思考，
以及这个模型认识哪些思考档位。

**优先级（全项目只有这一条）**：你在「模型管理 → 能力」里手工改的值 **>** 上游清单自己声明的值
**>** models.dev 的值 **>** 未声明。它只填上游没声明的空位，从不推翻上游已声明的 —— 上游那份是
「这条转发通道」的真实情况，models.dev 记的是模型在实验室
自己那套 API 上的能力，同一模型经不同通道能收的东西并不相同。

- **数据从哪来**：网关随包内嵌一份精简快照（构造时 `embed` 进二进制），所以离线、首次启动、
  访问不通时也有数据；开启后每 24 小时联网刷新一次，也可在面板里「立即刷新」。刷新成功覆盖，
  失败保留旧值（不会退回更旧的内嵌快照）。
- **关闭只停联网刷新**：已经拿到的数据继续用，模型清单照常工作。
- **在哪里看到**：`GET /v1/models` 广告的能力位、「模型管理」每行模型的能力来源标记
  （上游 / models.dev / 已覆盖）与思考档位都读这份数据；映射弹窗的思考等级下拉只列该模型
  真实认识的档位。
- **更新快照**：`node scripts/sync-modelsdev.mjs` 重新生成 `internal/modelmeta/modelsdev.json`
  （仓库检入的构建产物）。运行期刷新与脚本同口径，改一处要同步另一处。

## 调度形态：单号并发、换号间隔、退避与会话粘性

面板「设置 → 调度」里的一组开关，决定「一次请求在外部看起来是什么形态」。
上游风控看的不是单个请求，而是**同一账号在一段时间里接了多少互不相干的请求**：

| 项 | 作用 | 默认 |
|---|---|---|
| 在途租约 | 按「单号租约并发数」限制同一账号的并发请求，其余请求换号；关闭则不限 | 开启 |
| 单号租约并发数 | 同一账号最多同时持有几个在途租约，即单号并发上限 | 2 |
| 租约时长 | 单次独占的有效期；长回答按 1/3 滚动续期 | 300 秒 |
| 换号间隔 | 两次尝试之间等待多久，避免同一秒横扫号池 | 800 毫秒 |
| 失败后退避 | 403/5xx/网络抖动后，该号在窗口内暂不被选中 | 开启 |
| 退避起点 / 上限 | 退避时长逐次翻倍，封顶上限 | 2 秒 / 60 秒 |
| 会话粘性 | 同一段对话优先复用上次成功的账号 | 开启 |
| 会话绑定时长 | 绑定多久后失效 | 24 小时 |

几点设计与权衡：

- **退避不等于冷却**。冷却会改账号状态（面板上显示成限流/停用），退避只是调度层
  短暂跳过它。403、5xx、网络抖动属于上游波动，不该把号停掉，但也不该零间隔连打。
  调用成功即清空退避链。
- **租约走数据库 CAS**，不是进程内计数：多副本下也能保证同一账号的并发槽位不被超发。
  一个账号有「单号租约并发数」个槽位，由 `account_lease_slots` 表按 `(account_id, slot)`
  原子抢占；填 1 就是整号串行，填 2 即允许同号两路并发。
  租约到期自动失效，进程崩溃留下的残租约不会永久占号；面板里也能手动清。
- **换号比排队优先**。抢不到租约槽位时先换下一个号；号池里还有在线号、只是都在忙时
  会短暂等它空出来，而不是立刻把上一次的上游错误丢给调用方。
  需要进一步放大吞吐时，把「单号租约并发数」调大，或者直接关闭租约。
- **会话粘性只在能拿到会话标识时生效**。标识取 `X-Session-Id` / `X-Conversation-Id` /
  `session_id` / `conversation_id`；取不到就每轮正常选号。绑定的号失败时立即解绑，
  不会让一段对话死磕一个坏号。
- 注意区分两个「会话标识」：请求里给上游的 `X-RACCOON-Session-ID` 是**内容哈希**
  （每轮都变），会话粘性用的是**对话标识**（多轮不变）——前者是发给上游的协议头，
  后者是网关内部调度用的键。

---

所有打到小浣熊的上游请求（对话、签到、余额、续期、设备绑定）共用一份客户端身份：

| 项 | 作用 | 默认 |
|---|---|---|
| 对话端版本号 | `x-client-version`（对话面） | `1.0.35` |
| 管理面版本号 | `X-Client-Version`（余额/签到/刷新） | `v1.1.3` |
| 系统版本 | `x-client-os-version` | `10.0.26200` |
| 桌面平台 | `x-client-platform` | `desktop-windows-x64` |
| 对话端 UA | 对话面 `User-Agent` | 留空 = `raccoon-ai/<对话端版本号>` |
| 管理面 UA | 管理面 `User-Agent` | 留空 = `raccoon-ai/<管理面版本号>` |

几点说明：

- **UA 以前是漏发的**。Go 的 `net/http` 在没设置时会自动补 `User-Agent: Go-http-client/1.1`，
  于是上游看到的是「自称桌面客户端的六件套 + 一个 Go 程序」，这比不带头更像第三方工具。
  现在四套头（对话 / 管理 / 刷新 / 手机端）都会显式下发 UA。
- **UA 留空就是「跟着版本号走」**。派生发生在每次发送时，所以改完版本号 UA 会同步变，
  不会留下「新版本号 + 旧 UA」的自相矛盾。要完全自定义才需要显式填。
- **版本号会过期**。上游客户端发版后，旧版本号本身就是特征；面板里随手改即可，不用发版。
  新导入的账号也按这里填的平台与系统版本落库。
- 面板里四个版本/平台项不能留空，且会拒绝含换行等控制字符的值（避免把非法头发出去）。

## 日志管理

运行日志（进程输出）和调用流水（`usage_logs` / `checkin_history`）分开管理，都能在
面板「设置 → 日志管理」里改，保存后立即生效并持久化到数据库；环境变量只提供首次启动的默认值。

**运行日志文件**

- 写到 `LOG_DIR/relay.log`（默认 `DATA_DIR/logs`），同时保留标准错误输出，容器 `logs` 照旧可看。
- 单文件超过 `LOG_MAX_SIZE_MB` 或跨天时自动轮转成 `relay-YYYYMMDD-HHMMSS.log`。
- 旧归档按 `LOG_FILE_RETAIN_DAYS` 和 `LOG_MAX_FILES` 中更严格的一条清理：
  过期天数的先删，剩下的再按数量从最旧的删。
- 面板「运行日志」页的「日志存储与清理」里可以看文件清单、大小、下载单个文件，也能点「立即清理」。

**运行日志页（事件流）**

文件里的原始行只负责留底，排查问题看的是结构化事件流，落在 `runtime_events` 表：

- 进程里发生的事都写成一条事件：转发失败与换号、模型/账号冷却、冷却恢复、签到、凭证续期、
  版本更新、日志清理。级别分 `info` / `warn` / `error`，来源分 `relay` / `pool` / `checkin` /
  `renew` / `update` / `logs` / `account` / `system`。
- 每条事件带账号与可读的「处置」说明（例如「已换号重试」「仅冷却该模型」「标记需重登」），
  不用对照号池页倒推这次失败是怎么处理的。
- 相同事件会合并：内存里先按 (级别, 来源, 组件, 账号, 消息) 聚合，落库后再按 10 分钟窗口二次合并，
  列表显示 `×N` 与「近 N 次」，429 风暴不会把列表刷满。
- 写入走异步聚合（`internal/eventlog`），不阻塞转发热路径；事件写失败只打一行标准错误，不影响请求。
- `GET /api/logs/events?since=&until=&level=&scopes=&account=&q=&problem=&page=&pageSize=`：
  级别按「至少到这个程度」筛选（选警告会同时包含错误），`problem=1` 等价于只看 warn + error，
  同一次查询返回总数 / 警告数 / 错误数。
- `GET /api/logs/events/facets` 返回出现过的来源清单与中文标签，缓存 30 秒。
- 「实时刷新」与调用日志同一套策略：仅在本页且标签可见时轮询，切走即停，请求不叠加。
- 当前生效的筛选（来源、账号）在筛选条下面显示成可点掉的标签，点 `×` 即解除，
  不用再打开筛选弹层猜「为什么只剩这几条」。
- 详情弹层分「字段视图」和「原始记录」两个 tab，后者是可直接复制的 JSON；底部有「复制详情」。

**调用流水**

- `LOG_DB_RETAIN_DAYS`（默认 30）控制 `usage_logs`、`checkin_history` 与 `runtime_events` 保留天数。
- 清理按时间戳批量删除（每批 1000 条），不会一条 `DELETE` 卡住整个 SQLite 写锁。
- 设为 `0` 表示不按天数清理数据库，只清理日志文件。

**自动清理**

- `LOG_CLEAN_ENABLE` + `LOG_CLEAN_INTERVAL_MINUTES`（默认每小时）控制后台清理节奏。
- 启动时会先跑一次清理，避免停机很久后旧文件堆积。
- 手动「立即清理」不受开关影响，随时可用。

**调用日志页**

- 服务端分页：`GET /api/logs?page=&pageSize=`（每页最多 500 条），同一次查询顺带返回
  总数与失败数，历史流水再多也不会把浏览器拖死。
- 筛选都下推到 SQL：时间窗（`since`/`until`，毫秒）、`status`（`ok`/`fail`/`4xx`/`5xx`）、
  `account`、`model`、`api`，以及模糊搜索 `q`（模型 / 错误 / 接口 / 账号名或 uid）。
- `GET /api/logs/facets` 返回近 30 天出现过的模型与接口，供筛选下拉使用，结果缓存 30 秒。
- 「自动刷新」可按 5/10/30/60 秒轮询；只在停留在本页且标签页可见时生效，切走或最小化即停。
- 「列设置」可隐藏不常看的列，选择存在浏览器本地。

> 注意：`usage_logs` 是面板「调用日志」的数据源。保留天数设得太小会让统计窗口变短，
> 但不会影响号池与签到本身。

## 一键更新

面板「版本更新」页可以检查并安装新版本，不需要重新拉镜像或手动替换文件：

1. 进入 `/admin` → 「版本更新」→ 「检查更新」。默认从本项目 GitHub Release 的
   `relay-<os>-<arch>[.exe]` 资产取当前平台安装包。
2. 点「一键更新」：下载 → 校验 `checksums.txt` 里的 sha256 → 原子替换 → 重启。
3. 重启前会把旧版本留在 `relay.bak`，面板上有「回滚」按钮。

**Docker 部署**：新二进制安装在数据卷 `/data/bin/relay`，容器入口脚本会优先启动它。
这样重启、重建容器后更新都还在；想回到镜像自带的版本，删掉 `/data/bin/relay` 再重启。
容器内不需要额外权限，也不需要挂载 Docker socket。

**裸机部署**：替换的是当前可执行文件。Linux/macOS 用 `exec` 无缝重启；Windows 无法原地
重启，安装完成后按面板提示手动启动即可（新文件已经替换好）。

限制与注意：

- 只认 GitHub Release 资产并对 sha256 强制校验，缺 `checksums.txt` 的版本会被拒绝安装。
- 直连 GitHub 失败时自动改用镜像源：检查更新依次尝试 `gh-proxy.com`、
  `cdn.gh-proxy.org`、`o-o.men`，下载安装包同样逐个兜底，全部失败才报错。
  面板「版本更新」里的「下载来源」会显示本次实际用的是哪个源。
  可用 `UPDATE_MIRRORS` 换成自己的镜像列表（空格或逗号分隔）；旧版 `UPDATE_DOWNLOAD_BASE`
  仍然可用，填了它就只走该镜像、不再自动兜底。
- GitHub API 匿名调用有频率限制；限流时设 `GITHUB_TOKEN`，或用
  `UPDATE_API_BASE` 指向自建代理。
- 更新失败不会动当前版本；更新成功但新版本起不来，用「回滚」或删掉数据卷里的
  `bin/relay` 重启即可。

## 数据

默认存在 `DATA_DIR` 下的 `relay.db`（SQLite）；配置 `DATABASE_URL` 后存在 Postgres。
两种后端的表结构一致：

| 表 | 内容 |
|---|---|
| `accounts` | 账号、凭据（加密）、状态、冷却、签到台账 |
| `api_keys` | 数据面 Key（只存 sha256） |
| `model_cooldowns` | 模型级负缓存 |
| `account_cooldowns` | 账号级失败链（200108 等） |
| `checkin_history` | 每次签到的结果（含触发来源 auto / manual / onboard） |
| `usage_logs` | 调用流水 |
| `runtime_events` | 结构化运行事件（面板「运行日志」） |
| `settings` | 面板保存的运行期设置 |
| `schema_migrations` | schema 版本记录 |

备份方式：

- SQLite：拷 `data/` 目录。
- Postgres：`docker compose -f docker-compose.yml -f docker-compose.stack.yml exec postgres pg_dump -U relay relay > backup.sql`

无论哪种后端，里面都是加密后的凭据，`SECRET_KEY` 丢了就恢复不了；
SQLite 迁到 Postgres 也必须使用同一个 `SECRET_KEY`。

## 常见问题

**401 / 掉登录**
`refresh_token` 是单副本、用后轮换的。同一个号在多处（桌面客户端、另一台机器）同时刷新，
先刷的那次会把后刷的那份作废。对策：一个号只在一处用；已经在桌面端登录着的号，别再拿它的凭据到处跑。

**200035**
授权码是一次性的，已经被消费过了（通常是桌面客户端抢走了深链）。回授权页重新登录取新码。

**上游 403 / 面板显示「需重登」**
403 是风控、权限或设备指纹问题，不等于账号过期。遇到 403 会直接换号重试，**不冷却账号**，
也不会把号永久打成 `relogin`。如果面板上已经有号停在「需重登」、但你确定 token 还有效，
点该行的「刷新」：刷新成功会自动把它恢复成 `online`。

想知道某个号到底为什么被 403，点号池页「限流」列里的「详情」（或行末 `…` →「错误详情」）：
里面是上游那一次的响应头、请求 ID 和原始响应体，比面板上的一句话有用得多。

**积分耗尽 / 402 / 1000007**
号的钱花完了（上游常把 1000007 挂在 HTTP 400 上，按业务码识别）。面板上「查余额」确认，
换个号或者充值。该号会停在 `exhausted`，到下一次自动签到补分时自动复活；
自动签到关闭时回退为次日 04:00。

**面板打不开**
检查 `ADMIN_TOKEN` 是否填了；没填时它在启动日志里随机生成。端口默认只绑 `127.0.0.1`，
要从外网访问就改 `docker-compose.yml` 的端口映射，并在前面挂一层 HTTPS 反代。

**`数据库初始化失败: 建表失败: unable to open database file (14)`**
数据目录写不进去。容器以 uid 10001（`relay`）运行，而 bind mount 的宿主目录通常属于
`root` 或你自己的账号，写权限对不上。

v1.0.1 起镜像内置入口脚本，启动时会自动修正 `/data` 的属主，正常情况下不用管。
如果仍然报错（宿主文件系统不支持改属主，比如某些 NFS 卷），在宿主机执行：

```bash
sudo chown -R 10001:10001 ./data
# 或者文件系统不支持改属主时：
sudo chmod -R 777 ./data
```

v1.0.0 及更早的镜像没有入口脚本，必须先用上面的命令手工修权限。

## 发版

发版流程固定在 [`docs/releases/README.md`](docs/releases/README.md)，用脚本执行：

```bash
scripts/release.sh check v1.0.5    # 发版前检查（只读）
scripts/release.sh tag v1.0.5      # 打 tag 并推送，触发 CI
scripts/release.sh watch v1.0.5    # 等 CI、校验 Release 资产与 sha256
scripts/release.sh verify v1.0.5   # 下载本平台发布版实跑一次
```

发布说明存放在 `docs/releases/<tag>.md`，同时用作 tag 正文与 GitHub Release 说明。
`check` 会模拟 CI 环境（挪开被 gitignore 的 `internal/creds/testdata/`）跑一遍全量测试，
并逐项检查六平台交叉编译、`time/tzdata` 内嵌、更新器资产名与 CI 产物名是否一致。
每一项都对应一次实际踩过的坑，说明见该文档。
